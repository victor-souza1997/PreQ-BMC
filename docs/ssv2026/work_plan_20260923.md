**Deadline:** SSV 2026 paper, 6 pages IEEE, due **October 4, 2026**. That is

---

## 1. The goal, in one paragraph

PreQ-BMC is a tool that takes a trained neural network and produces a
**fixed-point quantized network (QNN)** as C code. The C code must be
**proved robust with ESBMC**, a bounded model checker for C. "Robust" means:
for one test image and every input within ε of it, the deployed C code
outputs the same class. The application is traffic-sign classification
(GTSRB, 43 classes) for Android Automotive. So the QNN must also keep the
accuracy of the float model.

### Hard rules (these cannot be broken)

1. **Soundness first.** Never trade soundness for a nicer result. If a fix
   needs a weaker contract, a tolerance, or disabled chaining, reject it and
   say why.
2. **Say which kind of claim each one is.** Every claim must be one of:
   - **PROVED**: ESBMC returned VERIFICATION SUCCESSFUL on a harness, and the
     harness is not vacuous.
   - **MEASURED**: an empirical number from running code on data.
   - **ASSUMED**: everything else.
3. **Negative results are fine.** TIMEOUT, INCONCLUSIVE, and REFUTED are
   honest outcomes. Never turn one into VERIFIED.
4. **The deployed arithmetic is fixed.** The proof must be about the exact
   integer C code that ships.
5. **Hardware limit:** 22 cores and 23 GB RAM, under WSL. Anything that builds
   a very large model in memory can crash the whole machine. This has already
   happened once. An Android (AOSP) build sometimes shares the machine and can
   take up to 20 GB.

## 2b. Update 2026-09-24: a new model fixes saturation, but the margin still fails

Overnight, Codex trained a **depthwise-pool model**,
`conv24_64_192_dwpool43`. Its last convolution is a 2×2 depthwise
convolution (groups = 192, stride 2) that acts as a learned pooling layer.
There is no dense hidden layer.

```
conv 5x5, 3->24,   s2 SAME   -> 16x16x24  = 6144 ReLU
conv 3x3, 24->64,  s2 SAME   ->  8x8x64   = 4096 ReLU
conv 3x3, 64->192, s2 SAME   ->  4x4x192  = 3072 ReLU
depthwise 2x2, 192, s2 VALID ->  2x2x192  =  768 ReLU
dense 768 -> 43 (logits)
```

160,523 parameters and 14,080 ReLUs.

| | value | kind |
|---|---|---|
| Validation accuracy | 90.36% | MEASURED |
| Float test accuracy | 91.32%, balanced 87.30% | MEASURED |
| Fixed-point C test accuracy | 91.35% | MEASURED |
| Float vs fixed disagreement | 0.26% of test images | MEASURED |
| Worst class | class 30 (ice/snow) at 45.3% | MEASURED |
| Python/C parity | 16 / 16 | MEASURED |

**Full proof attempt**, same image (class 12, ε = 1 byte):

- 605 of 607 ESBMC obligations VERIFIED. That covers 589 blocks and 4
  bridges.
- Total time: 2,027 s.
- Final status: **TIMEOUT**, not certified.

Bound widths at each bridge (MEASURED from the proved harnesses):

| bridge | neurons | median width | max width | full-range neurons |
|---|---:|---:|---:|---:|
| 0 -> 1 | 6144 | 14 | 72 | 0 |
| 1 -> 2 | 4096 | 52 | 236 | 0 |
| 2 -> 3 | 3072 | 1,324 | 3,714 | 0 |
| 3 -> 4 | 768 | 4,385 | 14,466 | **0** |

**Saturation is gone.** No hidden neuron reaches the full Q16 range. This is
real progress over the 91.54% model, where all 384 did.

**The final margin still fails**, for two reasons:

1. The margin check compares boxes: `low(logit_12) > high(logit_0)`. Both
   logits are clamped to the full range [−32768, 32767], so ESBMC returns
   FAILED in 0.16 s.
2. The exact fallback asks ESBMC for the 768 → 2 margin directly over the
   layer-3 box. It timed out at 120 s.

**The difference-row bound is also not enough** (my diagnostic, MEASURED in
Python from the harness arrays). This is the bound proposed in Problem 3:

| quantity (class 12 vs class 0, in logit LSB) | value |
|---|---:|
| margin at the box midpoint | +27,952 |
| worst-case deviation, `Σ \|w_t − w_c\| · width / 2 / 256` | 274,637 |
| sound lower bound on the margin | **−246,681** |

The margin at the box midpoint is positive. But the box at layer 3 is about
**10× too wide** for a sound difference-row bound to prove it. That gives a
concrete target: **cut the layer-3 box widths by at least 10×** (median below
about 400), while keeping the midpoint margin. This target applies to
certified training (Problem 1) and to any relational method (Problem 2).

## 2c. Update 2026-09-24 (afternoon): IBP training fails; relational bounds partly work

Two experiments on the depthwise-pool model. Both are MEASURED; neither is a
proof.

### IBP fine-tuning cannot keep 90% accuracy

Setup:
- IBP fine-tuning with the ε ramped from 0 to the target;
- the depthwise zeros kept exactly zero by a mask;
- temperature 1;
- selection on validation data only.

"Certified" in this table means the float IBP margin is positive at ε = 1.

| robust weight κ | learning rate | training ε | validation accuracy | float-certified |
|---:|---:|---:|---:|---:|
| 0 (baseline) | — | — | 90.36% | 0% |
| 0.5 (epoch 5) | 1e-4 | 1 | 52.9% | 8.7% |
| 0.02 (epoch 9) | 3e-5 | 0.9 | 77.1% | 0.01% |
| 0.005 (epoch 9) | 3e-5 | 0.9 | 82.6% | 0% |

The bounds do tighten a lot: the mean float margin at κ = 0.5 went from −1,200
to −3. But accuracy falls much faster than the bounds tighten. **Box-level
certified training at ε = 1 byte is not compatible with ≥ 90% accuracy for this
model.** Do not propose plain IBP again. CROWN-IBP (Zhang et al.) might give a
better trade-off, but that is untested.

### CROWN bounds on the unchanged 91% model certify some images

Method: standard CROWN backward linear bounds on the **deployed integer**
network. Each layer carries a ±½ rounding slack per neuron, and the bounds are
intersected with the exact integer boxes. The computation is float64, so this
is a diagnostic only. Each image takes about 9 s.

Results on 20 random validation images at ε = 1 byte, 19 of them correctly
classified:

| | box (current pipeline) | CROWN | sampled corners (true margin ≤ this) |
|---|---:|---:|---:|
| images with a positive margin bound | 0 / 300 | **2 / 19** | 19 / 19 |
| median margin lower bound | −187,120 | −5,655 | +1,901 (smallest sampled) |
| median width of the last hidden layer | 2,900–4,400 | ~100–570 | — |

- Every CROWN bound was checked against the sampled margins, and none exceeded
  them.
- CROWN is 10–40× tighter than boxes in the hidden layers.
- For 17 images the bound is still negative. The gap to the sampled margin is
  3× to 300×, with median about 5×.

**The open problem is now concrete:**

1. Can optimized relaxations close the remaining gap for a useful fraction of
   images at ε = 1, on the unchanged model? Candidates: α-CROWN (optimized
   lower slopes), β-CROWN (branch and bound on unstable ReLUs), or CROWN-IBP
   training.
2. **How can ESBMC certify a CROWN bound?** A CROWN certificate is a chain of
   per-neuron ReLU relaxation lemmas plus exact linear combinations. The
   per-neuron lemmas are one-dimensional and trivially ESBMC-checkable. The
   linear composition is large (about 14k neurons) but has no free inputs.
   Please answer these:
   - What is the smallest decomposition into ESBMC obligations that is sound?
   - Or: is "ESBMC proves the lemmas, and an exact rational checker proves the
     composition" acceptable as a verification claim? Under the rules in
     section 1, that composition step would be labelled differently from
     PROVED.

## 2d. Update 2026-09-24: memory-safe abstraction fail-fast

The exact final-layer retry over the 768-dimensional hidden box is no longer
started blindly. When the interval margin fails, the coordinator constructs
the adverse endpoint of that same abstract box and asks ESBMC to replay the
two deployed logits at that concrete hidden vector. A failed replay proves
only that the **abstract box** contains a violating point. It is not a
counterexample reachable from the image box, and the record is marked
`diagnostic_only` and `required_for_certificate=false`.

The cache-backed rerun is in
`output/sign_conv_depthwise_pool_proof_failfast_20260924/`:

| item | result | kind |
|---|---:|---|
| Previously established proof obligations | 605 VERIFIED | PROVED |
| Transition blocks covered | 589 / 589 | PROVED |
| Chaining bridges covered | 4 / 4 | PROVED |
| New ESBMC calls | 2 | MEASURED |
| Wall time | 8.88 s | MEASURED |
| Peak coordinator RSS | 1,303,584 KiB | MEASURED |
| Final status | `ABSTRACTION_INCONCLUSIVE` | MEASURED |
| Complete network certificate | false | MEASURED |

This change fixes resource behaviour, not abstraction precision. It prevents
an abstract counterexample that is already concrete inside the hidden box
from triggering a high-memory solver query over the same box. A network
certificate still requires a sound relational invariant that excludes the
point by connecting the hidden state to the raw input. `TIMEOUT`, a failed
abstract-witness replay, and a diagnostic CROWN bound never become
`VERIFIED`.

## 3. The blocking problem

### 3.1 The model

The 91.54% model, after batch norm has been folded into the weights:

```
input 32x32x3 (raw uint8, encoded as x/256 in Q16 with 8 fractional bits)
conv 5x5, 3->24,   stride 2, SAME  -> 16x16x24 = 6144 ReLU
conv 3x3, 24->48,  stride 2, SAME  ->  8x8x48  = 3072 ReLU
conv 3x3, 48->96,  stride 2, SAME  ->  4x4x96  = 1536 ReLU
conv 3x3, 96->128, stride 2, SAME  ->  2x2x128 =  512 ReLU
dense 512 -> 384                                =  384 ReLU
dense 384 -> 43                                    logits
```

There is also a variant without the dense 384 layer ("direct head"):
`conv24_48_96_128_direct43`, 186,587 parameters, **91.44% test accuracy**.

### 3.2 The deployed integer semantics (per neuron, identical in Python and C)

```
acc   = sum_i  w_int[i] * x_int[i]                  (__int128 accumulator)
value = round_half_away_from_zero(acc / 2^F) + b_int
value = clamp(value, -32768, 32767)                 (Q16)
if hidden layer: value = max(value, 0); value = clamp(value, ...)
```

Every layer uses Q16 with I = 7 and F = 8. Weights and biases are quantized to
steps of 1/256.

### 3.3 How the proof works today

Verification is **compositional, box to box**:

1. Start with the input box: each pixel is its value ±ε, with ε = 1 raw byte.
2. For each layer, compute a per-neuron integer interval `[low, high]` with
   sound interval arithmetic. That is IBP, done on the integer semantics.
3. ESBMC proves each layer step: "if the inputs are in box k, the outputs are
   in box k+1". It checks one receptive-field block at a time. These steps are
   cheap: 0.66 s per block.
4. Bridges prove that box k+1 is exactly what layer k+2 assumes.
5. Final step: prove that `logit[target] > logit[competitor]` for every
   competitor, over the last box.

### 3.4 Why it fails

The boxes grow with depth until they carry no information. These are
MEASURED widths at ε = 1 byte, taken from the proved bridge harnesses:

| bridge | neurons | median width | max width | neurons at the full Q16 range |
|---|---:|---:|---:|---:|
| 0 -> 1 | 6144 | 12 | 87 | 0 |
| 1 -> 2 | 3072 | 52 | 209 | 0 |
| 2 -> 3 | 1536 | 982 | 2,018 | 0 |
| 3 -> 4 | 512 | 11,888 | 30,955 | 0 |
| 4 -> 5 | 384 | **32,767** | **32,767** | **384 / 384** |

Every neuron entering the output layer is bounded by `[0, 32767]`, which is
all of Q16. ESBMC can prove that box, but the box is useless. In layers 2 to 5,
**0 ReLUs are stable**.

**The network itself is robust.** On the same ε-ball, the values the network
actually reaches stay small. Across 256 sampled corners, the maximum width is
**20** at every layer. The interval abstraction loses about **1600×** of
precision by block 4.

The failure is in the abstraction: a box forgets the correlations between
neurons. A faster solver does not help, because the input to the last step is
already vacuous.

### 3.5 A second, independent wall: the solver

Even with an artificially tight box that is **not sound** (max width 22),
ESBMC cannot finish a single 384 → 43 output query. It ran for about 22
minutes, used 20.3 GB of RAM, and was stopped. The same query for the old tiny
model (18 → 43) takes 3 to 36 s. The query grew 20× in size (118,151 vs 5,789
VCCs). After simplification it is one large margin constraint.

## 5. What must be done, in priority order

### P0. Decide the strategy today

There are two ways to get a real VERIFIED result:

- **(A) Certified training.** Make the network's own interval bounds tight,
  so the existing box-to-box ESBMC pipeline succeeds unchanged. Our pipeline
  is literally **integer IBP checked by ESBMC**. A network trained so that
  float IBP certifies the margin should therefore certify in our pipeline too,
  up to rounding. **This is the most promising path.** It reuses everything
  that already works and needs no new proof theory.
- **(B) A tighter sound abstraction.** Replace boxes with contracts that keep
  correlations, for example DeepPoly/CROWN linear bounds in terms of the
  input, each proved by ESBMC. This is more research, needs new harness types,
  and is high-risk in 11 days.

**Fallback (C)**, which should run in parallel as insurance: an
accuracy-versus-verifiability curve over 1-, 2-, 3- and 4-stage models. Only
fully proved models may be called certified. The deep model is reported as the
measured limit of scalability.

### P1. Certified training that keeps ≥ 90% accuracy (path A)

- Take the depthwise-pool model (section 2b) and fine-tune it with IBP or
  CROWN-IBP at ε ≈ 1–2/256. The target is layer-3 box widths at least 10×
  smaller.
- It must keep at least 90% validation accuracy. The test set is used only
  once, after selection.
- The training must be **quantization-aware**. The certificate is about the
  integer model, not the float one.
- Success criterion (MEASURED first, cheap): integer interval propagation
  gives a positive lower bound on the final margin for most correctly
  classified test images. Only then run ESBMC.

### P2. Make the final margin step provable and cheap

- The margin must be bounded with the **difference row** `(w_t − w_c)`, not
  as `lower(logit_t) − upper(logit_c)`. See problem 3 in section 6.
- The ESBMC competitor harness must compute only the two logits involved, not
  all 43.

### P3. Run the evaluation cohort (after P1 works)

- 18 images: 2 correctly classified images per class, from 9 classes.
  - Weak classes: 27 pedestrians (50%), 30 ice/snow (54.7%), 0 20 km/h (65%).
  - Median classes: 19, 12, 39 (about 92–93%).
  - Strong classes: 15, 16, 32 (100%).
- ε ∈ {1, 2, 4} bytes, giving **54 regions**.
- Budget: about 27 min cold per region for the 4-stage model, so about 24 h
  serial. Report every verdict, including TIMEOUT.

### P4. Fallback curve (path C)

- Run the same pipeline on the shallow models: 1 stage (old model, 41.8%),
  2 stages (about 66%), 3 stages (about 87–89%), 4 stages (91.4%).
- Report accuracy and verified fraction for each.

### P5. Housekeeping (on the repo machine)

- Commit the convolution-native work. It is still uncommitted.
- One pre-existing test failure is still open:
  `test_iris_block_size_zero_and_one_select_consistent_qif`. It fails on
  committed HEAD too, so it is not new.
- Android device parity, latency, and energy are all NOT_MEASURED. They need
  the physical device.

### Problem 1: a certified-training recipe that keeps accuracy

**Context.** GTSRB, 32×32×3 inputs scaled to [0, 1), 43 classes.
**Start from the depthwise-pool model in section 2b.** It is the best
candidate: 91.32% test accuracy and no saturation. The concrete goal is to
cut its layer-3 interval widths by at least 10× while keeping at least 90%
validation accuracy. Batch norm is used in training and folded into the weights for
deployment. The target is ε = 1/256 in L∞ (one raw byte). Training runs on
CPU at about 5–12 s per epoch and about 3 GB RSS.

**What happened.** Our IBP attempts either destroyed accuracy (11%) or cost
7 points (83.8%). See section 4.

**Give us:**

- (a) The loss: IBP or CROWN-IBP, and the mixing schedule κ (clean vs
  robust). Should the robust term use the **logit-difference** worst case
  `upper(z_j − z_y)`? We believe that removes the scaling problem.
- (b) The ε schedule: the warm-up ramp length, and the train ε versus the
  target ε. Rounding adds up to 1/256 per neuron per layer, so how much extra
  ε should training use?
- (c) Fine-tune from the 91% checkpoint, or train from scratch with IBP
  initialization (Shi et al. 2021)? How should batch norm be handled during
  IBP?
- (d) How to make training quantization-aware: weights rounded to 1/256
  (straight-through estimator), and activations rounded and clamped at
  32767/256 ≈ 128.
- (e) What clean accuracy to expect at ε = 1/256 on GTSRB with this
  capacity. Cite the literature if you can: IBP (Gowal et al. 2018),
  CROWN-IBP (Zhang et al. 2020), SABR (Müller et al. 2023), and "fast
  certified training" (Shi et al. 2021).

### Problem 2: why do boxes collapse, and what is the cheapest sound fix?

Given the width table in section 3.4, estimate the per-layer growth factor.
Rows have about 75–864 nonzero weights, and weights are quantized to 1/256.
For a naturally trained network, is the collapse expected at this depth?

If certified training (Problem 1) is not enough, what is the minimal sound
extension of our **box-to-box, ESBMC-checked** contract language that keeps
correlations? Options:

- linear bounds in terms of the previous layer (DeepPoly-style), where each
  bound is proved per neuron by ESBMC over its receptive field;
- a few relational "cuts" `d · h ≤ c`, each proved by ESBMC before it is
  assumed;
- input splitting. Probably hopeless: 3072 dimensions.

For each option, what does the ESBMC harness look like, and how big does it
get at layers 3 and 4?

### Problem 3: a sound, cheap final-margin certificate

At the last layer, `out_t − out_c` must be strictly positive over the box of
hidden values `h ∈ [L, H]` (integers, ≥ 0).

**Our proposed argument. Please check its soundness.**

With `s = 2^F` and round-half-away-from-zero, `|round(a/s) − a/s| ≤ 1/2`.
So:

```
round(a_t/s) − round(a_c/s) ≥ (a_t − a_c)/s − 1
a_t − a_c = (w_t − w_c) · h
```

The minimum of `(w_t − w_c) · h` over the box is attained at a corner and can
be computed exactly: take `L_i` where the coefficient is positive and `H_i`
where it is negative.

Then `v_t − v_c ≥ min((w_t−w_c)·h)/s − 1 + (b_t − b_c)`.

The final clamp is monotone. So strictness survives if `v_t > v_c` and
`v_c < 32767` and `v_t > −32768`. These side conditions come from interval
bounds.

**Measured on 2026-09-24 (section 2b):** this bound is needed but not
enough. On the depthwise-pool model it gives −246,681, against a midpoint
margin of +27,952. It will only prove the margin once the upstream boxes are
about 10× tighter.

**Questions:**

- Is this sound for the exact integer semantics in section 3.2? Check integer
  division, negative values, and the half-way case.
- The generic rounding lemma (the `−1` slack) is independent of the image. It
  could be proved **once** by ESBMC, and the corner evaluation redone per
  image. Is that split acceptable under the "PROVED" definition, or must the
  per-image step also go through ESBMC? If it must, what is the smallest
  harness that checks it? Our guess: 2 dot products over 512 inputs, with no
  other logits.
