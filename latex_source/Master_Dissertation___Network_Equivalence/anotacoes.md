## Overview and Motivation

The verification of quantized neural networks (QNNs) presents a fundamental challenge in safety-critical applications: ensuring that the conversion from floating-point to fixed-point arithmetic does not compromise the network's robustness properties. Our methodology addresses this challenge by combining abstract interpretation techniques with bounded model checking to provide formal guarantees about the behavior of quantized networks under input perturbations. The goal is to take a trained deep neural network (DNN), an input uncertainty region defined as an L∞ ball around a sample input, and a target classification, and determine a per-layer fixed-point quantization scheme that preserves the property that the target class remains the maximum output (argmax) for all inputs within the uncertainty region.

The approach decomposes this global verification problem into a series of layer-wise verification tasks. First, we use the DeepPoly abstract interpretation framework to prove that the original floating-point DNN satisfies the robustness property and to compute admissible output intervals for each layer. These intervals, called preimages, define the set of values that each layer's outputs must stay within to ensure that subsequent layers will ultimately produce outputs respecting the global robustness property. Then, for each layer independently, we verify that its quantized implementation using fixed-point arithmetic produces outputs that remain within these admissible intervals, using the ESBMC (Efficient SMT-Based Context-Bounded Model Checker) tool to exhaustively explore all possible behaviors under the specified input ranges.

## Input Region Definition and Initialization

The verification process begins by defining the input uncertainty region in the main entry point (Quadapter_robustness_main.py). Given a sample input `x_input` and a perturbation radius `ε`, the input bounds are computed as `x_low = clip(x_input - ε, 0, input_scale)` and `x_high = clip(x_input + ε, 0, input_scale)`, where the clipping operation ensures that perturbed inputs remain within the valid domain of the input features. For image datasets like MNIST, this typically means staying within the [0, 255] range before normalization, while for other datasets like Iris, the clipping bounds are determined by the natural feature ranges. These bounds are then normalized according to the preprocessing used during model training and passed to the verification framework.

The `GPEncoding` class receives these normalized bounds as `x_low_real` and `x_high_real` and stores them in the input layer structure through the `assert_input_box` method. This method initializes `self.input_layer.lb` and `self.input_layer.ub` with the provided bounds and configures the DeepPoly analysis engine to use this input box as the starting point for symbolic propagation. The input layer serves as the foundation for all subsequent bound computations, representing the set of all possible inputs that must be considered during verification.

## Symbolic Bound Propagation with DeepPoly

Once the input region is established, the `symbolic_propagate` method invokes the DeepPoly abstract interpretation framework to compute concrete lower and upper bounds for every neuron in the network. DeepPoly performs a forward pass through the network, maintaining symbolic linear constraints that express each neuron's output as a function of the input variables. For each affine transformation (matrix multiplication followed by bias addition) and each ReLU activation, DeepPoly computes both concrete bounds (numerical lower and upper values) and symbolic constraints that relate outputs to inputs.

The results of this propagation are stored in the layer structures throughout the network. For each layer `l`, the framework maintains several sets of bounds: `l.lb` and `l.ub` represent the bounds on the affine transformation outputs before the ReLU activation is applied, capturing the full range of pre-activation values including negative numbers. The bounds `l.clipped_lb` and `l.clipped_ub` represent the post-activation values after applying the ReLU operation, which clips negative values to zero. These clipped bounds are particularly important because they represent the actual inputs to the next layer in the network. For the output layer specifically, the bounds `self.output_layer.lb` and `self.output_layer.ub` capture the admissible ranges for the network's logits (pre-softmax classification scores) over the entire input uncertainty region.

## Network-Level Robustness Verification

Before proceeding with quantization, the methodology first verifies that the original floating-point DNN satisfies the robustness property. This check occurs in the initial stage of the `verified_quant` method and serves as a prerequisite for all subsequent quantization efforts. The verification examines whether the lower bound of the target class logit exceeds the maximum upper bound of all other classes: `target_lb = output_layer.lb[targetCls]` and `other_max_ub = max(output_layer.ub[i] for i ≠ targetCls)`. If `target_lb ≥ other_max_ub`, then we can conclude that for every input in the uncertainty region, the target class will have the highest logit value, guaranteeing correct classification.

This verification is sound because DeepPoly provides rigorous over-approximations of the reachable outputs. If the bounds computed by DeepPoly do not satisfy the robustness condition, then the network is genuinely not robust for this input region, and no quantization can fix this fundamental issue. In this case, the verification process terminates early, reporting that the property does not hold in the DNN. Only when this initial check passes does the methodology proceed to the quantization verification phase.

## Backward Preimage Computation

The backward preimage computation phase, implemented in `backward_preimage_computation`, is crucial for decomposing the global verification problem into layer-wise subproblems. Starting from the output layer and working backward through the network, this method computes for each hidden layer a set of admissible output intervals that are sufficient to guarantee the final robustness property. These intervals, stored as `l.relaxed_lb` and `l.relaxed_ub` for each layer `l`, define a "safe zone" that the layer's outputs must remain within.

For the output layer, the relaxed bounds are simply set equal to the concrete bounds computed by DeepPoly, since these directly represent the admissible final outputs. For each hidden layer, the method performs a backward propagation through the weight matrix of the subsequent layer. Given the admissible intervals `[pre_lo, pre_hi]` for the next layer's inputs and the weight matrix `W_next` and bias `b_next` of the connection, the method computes conservative bounds on the current layer's outputs by solving an interval arithmetic problem. For each neuron `j` in the current layer, the contribution to the next layer's constraint is computed by summing the weighted contributions across all neurons in the next layer, accounting for the signs of the weights to maintain sound over-approximations.

This backward propagation is conservative in the sense that the computed preimages may be larger than strictly necessary, but they guarantee that if a layer's outputs fall within its preimage, then all subsequent layers will behave correctly. This conservatism is essential for soundness: we cannot afford to underestimate the required ranges, as that would invalidate the verification guarantees. The preimage intervals serve as the verification targets during the subsequent ESBMC-based quantization search.

## Quantization Search with ESBMC

The `forward_quantization_with_esbmc` method implements the core quantization verification loop, systematically searching for the coarsest acceptable quantization for each layer. The method iterates through layers from input to output, and for each layer, it explores a range of bit-width configurations specified by the command-line parameters `bit_lb` and `bit_ub`. For each candidate bit-width `all_bit`, the method tries different divisions between integer bits and fractional bits, where `frac_bit` determines the position of the fixed-point and `int_bit = all_bit - frac_bit` determines the range of representable values.

For a given configuration, the layer's weights and biases are quantized by scaling them by `2^frac_bit` and rounding to the nearest integer: `qu_w = round(weights × 2^F)` and `qu_b = round(biases × 2^F)`. This quantization scheme represents values in QF format, where arithmetic operations are performed on integers that implicitly represent fixed-point values with F fractional bits. The quantized parameters, along with the bit configuration and the relevant bounds (input bounds from the previous layer and preimage bounds for the current layer), are then passed to `verify_layer_with_esbmc`.

The search strategy is greedy: for each layer, the method tries bit-widths from smallest to largest, and for each bit-width, it tries configurations with different fractional bit allocations. As soon as ESBMC successfully verifies a configuration, that configuration is recorded for the layer and the search proceeds to the next layer. If no configuration within the specified range can be verified, the entire quantization search fails for that network. This greedy approach prioritizes finding minimal bit-width solutions, which is desirable for hardware efficiency, while still maintaining formal correctness guarantees.

## ESBMC Harness Generation

The `generate_esbmc_verification_code` method produces C source code that serves as the verification harness for ESBMC. This code generation is template-based and depends on whether the layer being verified is a hidden layer or the output layer, as these two cases require fundamentally different verification properties. The generated code represents all arithmetic in fixed-point using 32-bit integers for values (QF format) and 64-bit integers for intermediate accumulations (Q2F format, with double the fractional bits).

For hidden layers, the method uses the `innerlayer_fixed_int` template from abstract.py. This template generates a C program that nondeterministically assumes input values within the bounds specified by the previous layer's clipped outputs (`in_layer.clipped_lb` and `in_layer.clipped_ub`), performs the quantized affine transformation using the provided quantized weights and biases, and then asserts that each output element falls within the preimage bounds for the current layer (`cur_layer.relaxed_lb` and `cur_layer.relaxed_ub`). The property being verified is thus: "For all inputs within the specified range, the fixed-point computation of `y = Wx + b` produces outputs that remain within the admissible preimage intervals."

For the output layer, the method uses the `outerlayer_fixed_int` template, which verifies a different property: the argmax robustness property. Instead of checking inclusion in a preimage (which doesn't make sense for the final layer, as there are no subsequent layers), the output layer template verifies that for all inputs within the range, the quantized logit for the target class strictly exceeds the logits for all other classes: `out[targetCls] > out[i]` for all `i ≠ targetCls`. This directly encodes the classification robustness property at the network level.

## Fixed-Point Arithmetic Implementation

The fixed-point arithmetic implementation in the generated C code is carefully designed to avoid both overflow and loss of precision. All input values, weights, and biases are represented in QF format with F fractional bits, meaning they are integers that represent real values scaled by `2^F`. When computing the affine transformation `y = Wx + b`, each weight-input product `w × x` produces a value in Q2F format (with 2F fractional bits), as multiplying two QF values doubles the fractional precision. To accumulate these products without overflow, the code uses 64-bit signed integers (`long long` in C), which provide sufficient range for the sum of products even in large layers.

The bias term requires special handling: since biases are stored in QF format but need to be added to the Q2F accumulator, they are first left-shifted by F bits (`bias_q << F`) to convert them to Q2F format before addition. After all weight-input products and the bias have been accumulated, the result is shifted right by F bits (`acc >> F`) to convert back from Q2F to QF format. This shift effectively performs a division by `2^F`, implementing the scaling correction required to return to the original fixed-point representation. Finally, the result is saturated to fit within the range of a 32-bit signed integer, clipping to `INT_MIN` or `INT_MAX` if the value would overflow.

The conversion of floating-point bounds to integer bounds is performed conservatively to maintain soundness. Lower bounds are converted using the floor operation (`floor(bound × 2^F)`) to ensure the integer bound is not above the real bound, while upper bounds use the ceiling operation (`ceil(bound × 2^F)`) to ensure the integer bound is not below the real bound. This conservative conversion guarantees that the integer constraints in the C harness are at least as strict as the real-valued constraints, preserving the soundness of the verification.

## ESBMC Execution and Result Interpretation

The `run_esbmc_verification` method executes the ESBMC tool on the generated C harness and interprets the results. ESBMC is invoked with a carefully chosen set of command-line options that balance verification power with execution time. The `--floatbv` option enables precise reasoning about floating-point and integer arithmetic, while `--z3` selects the Z3 SMT solver as the backend decision procedure. The `--incremental-bmc` option enables incremental bounded model checking, which can improve performance by reusing solver state across different unrolling depths. The `--unwind` option specifies the loop unrolling depth, which must be sufficient to fully explore all loop iterations in the verification harness. A timeout is set to prevent the verifier from running indefinitely on difficult instances.

ESBMC's output is parsed to determine the verification outcome. If the output contains the string "VERIFICATION SUCCESSFUL", the tool has proven that all assertions hold for all possible inputs within the specified bounds, and the layer configuration is accepted. If the output contains "VERIFICATION FAILED", ESBMC has found a counterexample—a concrete input assignment that violates one of the assertions, indicating that the quantization is too coarse for this configuration. The counterexample includes the specific input values and intermediate computation results that led to the violation, which can be valuable for debugging but is typically just logged for future analysis. If neither success nor failure is reported, or if the tool times out, the result is classified as "UNKNOWN", and the method proceeds to try the next quantization configuration.

## Correctness and Soundness Guarantees

The overall methodology provides formal soundness guarantees through the composition of sound techniques. DeepPoly's over-approximation ensures that the computed bounds on neuron activations are conservative: every reachable value is within the computed bounds, though the bounds may include unreachable values. The backward preimage computation maintains this conservatism, computing for each layer a set of admissible outputs that is sufficient (though possibly larger than necessary) to guarantee correct final outputs. ESBMC's bounded model checking provides complete verification within the specified bounds and unrolling depth: if ESBMC reports success, then the quantized arithmetic provably satisfies the assertions for all inputs in the range.

The composition of these techniques preserves soundness: if every hidden layer's quantized affine outputs fall within their respective preimage bounds (verified by ESBMC on the hidden layer harnesses) and if the output layer satisfies the argmax property (verified by ESBMC on the output layer harness), then the complete quantized network satisfies the global robustness property over the input uncertainty region. This follows from the transitivity of correctness: if each layer's outputs are correct given correct inputs, and the input layer receives inputs within the specified bounds, then the final outputs must satisfy the desired property.

## Implementation Details and Key Code Locations

The methodology is implemented across several key files in the codebase. The main entry point in Quadapter_robustness_main.py handles input region definition and calls the verification framework. The core verification logic resides in quadapter_encoding_robustness.py, which contains the `GPEncoding` class with methods for input box assertion (`assert_input_box`), symbolic propagation (`symbolic_propagate`), backward preimage computation (`backward_preimage_computation`), quantization search (`forward_quantization_with_esbmc`), ESBMC harness generation (`generate_esbmc_verification_code`), and ESBMC execution (`run_esbmc_verification`). The C code templates for ESBMC harnesses are defined in abstract.py, with `innerlayer_fixed_int` handling hidden layers and `outerlayer_fixed_int` handling the output layer. Supporting utilities for quantization and bound manipulation are provided in quadapter_utils.py, while the DeepPoly implementation is in DeepPoly_quadapter.py.

The layer encoding structure, defined by the `LayerEncoding` class, serves as the central data structure for maintaining per-layer information. Each layer stores its size, parameters (weights and biases), concrete bounds from DeepPoly (`lb`, `ub`), post-activation bounds (`clipped_lb`, `clipped_ub`), relaxed preimage bounds (`relaxed_lb`, `relaxed_ub`), and quantization metadata (integer and fractional bit allocations). This structure provides a clean interface for accessing layer-specific information during both bound propagation and quantization verification.

## Common Issues and Best Practices

Several common pitfalls can compromise the soundness or effectiveness of the verification process. Normalization mismatches occur when the input bounds `x_low` and `x_high` use a different scaling than the model expects, leading to verification of the wrong input region. It is critical to ensure that the same normalization applied during training is applied to the input bounds during verification. Another common error is attempting to use the output layer's bounds (`output_layer.lb/ub`) as preimage bounds for hidden layers; this is incorrect because hidden layer preimages must be computed backward from the output constraints through the intervening weight matrices, not taken directly from the final layer.

Arithmetic overflow represents a significant risk if insufficient precision is used for intermediate computations. Using 32-bit accumulators for the sum of products in fixed-point arithmetic can easily overflow in networks with large layers or high precision requirements. The methodology avoids this issue by using 64-bit accumulators for intermediate sums and only converting back to 32-bit after the final shift operation. Verification timeouts can occur when ESBMC is asked to verify layers with many neurons or complex bound constraints. In such cases, increasing the timeout value or adjusting the unrolling depth may help, though ultimately some configurations may be too complex for bounded model checking to handle within reasonable time limits.
